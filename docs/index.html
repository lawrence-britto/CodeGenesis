Why this exists

Turning a mapping workbook into SQL is slow, and small mistakes travel far

Engineers spend real hours re-reading the same workbook tabs, joins, and rule sheets by hand. CodeGenius doesn't remove that work — it removes the repetitive parts of it.

Time

The same workbook tabs, source SQL, joins, and rule references get inspected over and over for every new map group.

Manual error

Blank identifiers, inconsistent names, wrong joins, and unresolved rules can quietly survive into generated SQL.

Review effort

Analysts and developers have to reconstruct why an expression or join was written the way it was.

Test-data friction

Realistic test data is hard to create without either copying sensitive rows or losing the shape of real data.

Architecture

How the pieces fit together

One request, one deterministic path. The AI layer sits off to the side — consulted for advice, never in the critical path of a decision.

Who decides what

The checks are deterministic and AI advises based on the rules.

Every pass, fail, and review status is calculated by ordinary code before a model ever sees it. When a check fails, a local model (Qwen, via Ollama) is consulted for advice — it suggests likely causes and next steps based on the deterministic finding and the bank's approved rulebook, and never rewrites the report. Is the workbook usableMapping ValidatorAdvises on failure only
Required-field checks, blank-value detection, and duplicate-target checks are plain code. Qwen is consulted only when validation fails — it suggests a likely fix based on the deterministic finding, and never changes the PASS/FAIL result.
What the SQL containsSQL Generator & fixersAdvises on failure only
Expressions, joins, and TODOs come from the workbook and configuration. Qwen is consulted only when something fails — it suggests context for a warning or TODO, but cannot write, edit, or approve SQL.
Shape of test dataSample profilerAdvises on failure only
Types, ranges, and category weights come from statistical analysis of the sample file. Qwen is consulted only if the quality check fails — it suggests what to inspect, without touching the generated data.
Whether two files differDiff & structural comparatorAdvises on failure only
A text diff and a parsed structural comparison produce the same result for the same two files, every time. Qwen is consulted only for high-risk findings — it suggests what to review, and never edits the diff.
Explaining a findingApproved rulebookSuggests, based on the rule
When a check fails, Qwen receives only the deterministic finding and matching approved rule text — never raw production data — and returns a short, reviewable suggestion. It cannot rewrite the report or change the status.
Whether to deployBA, developer, release ownerNever
No status produced by CodeGenius is a release approval. That decision stays with the bank's existing process.

Guardrails

What keeps this trustworthy

✓

An AI explanation is never treated as proof that SQL is correct — the deterministic checks are the evidence.

✓

Production data stays out of AI prompts; only findings and metadata are sent for explanation.

✓

Generated SQL, TODOs, warnings, and join changes are reviewed by a person before release, every time.

✓

The approved-knowledge index is rebuilt whenever the bank's rulebooks change, so explanations stay current.

✓

Uploads, generated output, and logs are treated as local, environment-specific data, not shared defaults.
